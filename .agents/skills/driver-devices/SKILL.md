# SKILL: Драйвер устройств

## Назначение

Реализация и подключение устройств (ввода-вывода) к виртуальной машине.

## Область

- `src/uxn-types.ts` — интерфейс `Device` (каноническое определение).
- `src/Device.ts` — совместимый реэкспорт.
- `src/ConsoleDevice.ts` — пример устройства вывода в консоль.
- Опкоды `DEI`/`DEO` в `src/opcodes/dev-ops.ts` — точка вызова устройства.

## Ключевые факты

### Контракт `Device`

```ts
interface Device {
    dei(vm: VMState, target: number): void;   // чтение порта
    deo(vm: VMState, target: number): boolean; // запись; false => останов ВМ
}
```

- Устройство получает `VMState` (не класс `Uxn`).
- Порт (`target`) — адрес в диапазоне `0x00..0xff` (256 байт `vm.dev`).
- `deo` возвращает `false`, если ВМ должна остановиться; тогда `opDeo` вернёт
  PC `-1`.

### Как устройство вызывается

- `opDei` кладёт на стек `vm.dev[addr]` после вызова `device.dei(vm, addr)`.
  В `SHORT` (`DEI2`) читаются два соседних порта.
- `opDeo` сначала записывает значение в `vm.dev[addr]`, затем вызывает
  `device.deo(vm, addr)`. Стек: `( value addr -- )`, значение на вершине.

### Пример: `ConsoleDevice`

- Порт консоли — `0x18`.
- `deo` при `target === 0x18` печатает символ: `process.stdout.write(...)` в Node,
  иначе `console.log(...)`.
- `dei` — заглушка (обнуляет порт), ввод не реализован.

## Правила

- Новое устройство реализует интерфейс `Device` (методы `dei` и `deo`).
- Определение интерфейса держать только в `uxn-types.ts`; `Device.ts` — реэкспорт.
- ВМ должна получать устройство через конструктор: `new Uxn(device)`.
- Не менять контракт `deo` так, чтобы падение устройства бросало исключение —
  сигнал остановки только через `false`.
- Возврат `false` использовать осознанно: это прекращает `run`.

## Проверка

- Устройство печатает символ: программа `LIT 0x18, LIT char, DEO` выводит `char`.
- `node dist/examples/hello.js` печатает `Hello` через `ConsoleDevice`.
- `npm run build` без ошибок.

Связанные скилы: `vm-core`, `opcodes`, `examples`.
