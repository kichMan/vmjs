# SKILL: Immediate-опкоды

## Назначение

Работа с семейством `LIT`.

## Область

- `src/opcodes/immediate-ops.ts`
- Вызов из `src/uxn-vm.ts` (метод `executeOp`).

## Ключевые факты

### Почему это отдельный диспетчер

`LIT` — не отдельный слот таблицы `0x00..0x1f`, а **семейство базового опкода
`0x00`**, различаемое старшими битами (как `case 0x00` в `uxn.c`). Поэтому в
`Uxn.executeOp` есть спец-случай:

```ts
if (baseOp === 0x00 && op !== 0x00) {
    return opImmediate(this, op, pc);
}
```

Чистый `0x00` — это `BRK`, он обрабатывается таблицей.

### Семейство `LIT` (байт — базовый `0x00` + флаги)

| Байт | Опкод | Действие | PC |
|:----:|-------|----------|:--:|
| `0x80` | `LIT` | `push(M[PC])` (рабочий стек) | `+1` |
| `0xa0` | `LIT2` | `push(M[PC]<<8 \| M[PC+1])` | `+2` |
| `0xc0` | `LITr` | `LIT`, но в стек возвратов | `+1` |
| `0xe0` | `LIT2r` | `LIT2`, но в стек возвратов | `+2` |

Биты: `0x80` — признак `LIT`, `0x40` — возвратный стек (`r`), `0x20` — два байта
(`2`). Порядок чтения слова — big-endian, как в `pushShort`.



### Неиспользуемые слоты базового `0x00`

`0x40` (JMI), `0x60` (JSI) — не реализованы и попадают в ветку `console.warn`.

## Правила

- Не переносить `opBrk` в `immediate-ops.ts`: чистый `BRK` (`0x00`) — часть
  таблицы.
- Не назначать байтам `0x80/0xa0/0xc0/0xe0` другое поведение.
- При добавлении нового расширения использовать свободные слоты базового `0x00`
  (`0x40`, `0x60`) и документировать неканоничность.
- Сохранять big-endian при чтении `LIT2`/`LIT2r`.

## Проверка

- `LIT 0x42` -> стек `[0x42]`; `LIT2 0x1234` -> `[0x12, 0x34]`.
- `LITr 0x05` -> значение в `ret`; `LIT2r 0x1234` -> `ret = [0x12, 0x34]`.
- `npm run build` без ошибок.

Связанные скилы: `opcodes`, `vm-core`.
