# SKILL: Опкоды (базовые)

## Назначение

Добавление и изменение базовых опкодов `0x00..0x1f`, работа с таблицей
диспетчеризации и группировкой по файлам.

## Область

- `src/opcodes/stack-ops.ts` — `INC POP NIP SWP ROT DUP OVR STH`
- `src/opcodes/flow-ops.ts` — `BRK JMP JCN JSR`
- `src/opcodes/mem-ops.ts` — `LDZ STZ LDR STR LDA STA`
- `src/opcodes/dev-ops.ts` — `DEI DEO`
- `src/opcodes/algebra-ops.ts` — `EQU NEQ GTH LTH ADD SUB MUL DIV AND ORA EOR SFT`
- `src/opcodes/index.ts` — реэкспорт
- `src/opcode-table.ts` — `OPCODE_TABLE`

## Ключевые факты

### Формат опкода

Каждый опкод — функция сигнатуры `OpcodeFn`:

```ts
(vm: VMState, flags: OpcodeFlags, pc: number) => number | null
```

- принимает `VMState` (не класс `Uxn`) — это разрывает цикл зависимостей;
- читает операнды через `getStack(vm, flags)` и хелперы из `../stack.js`;
- возвращает новый PC (обычно тот же `pc`) либо `null` (только `BRK`).

### Группировка и таблица

- Операндные опкоды следуют шаблону «pop двух значений -> операция -> push».
- Унарные (`INC`, `POP`, `DUP`, ...) — одним значением.
- Порядок операндов: со стека **сначала снимается вершина** (`b`), затем
  следующий (`a`). Например `SUB`: `b = pop`, `a = pop`, результат `a - b`.
- Каждый базовый опкод регистрируется в `OPCODE_TABLE` по ключу базового номера.

### Порядок операндов для операций записи

`STZ`, `STR`, `STA`, `DEO` читают стек как `( addr value -- )`, то есть
**значение на вершине**, адрес — под ним. Это зафиксировано и проверено.

### Маскирование

Арифметика обязана усекаться: `(a + b) & 0xff` или `& 0xffff` для `SHORT`.
`DIV` защищён от деления на ноль (даёт `0`).

## Правила

- Не импортировать класс `Uxn` — только `VMState` (тип) из `../uxn-types.js`.
- Все импорты с расширением `.js`.
- Новый опкод добавить в подходящий файл группы, экспортировать через
  `opcodes/index.ts` и зарегистрировать в `OPCODE_TABLE`.
- Не занимать базовый слот `0x00` обычным опкодом: этот слот принадлежит семейству
  `BRK/LIT*` (см. скил `immediate-opcodes`).
- Все 32 базовых слота `0x00..0x1f` уже заняты — расширения возможны только на
  байтах с `baseOp == 0x00`.

## Проверка

- `npm run build` без ошибок.
- `OPCODE_TABLE` содержит ровно 32 записи `0x00..0x1f`.
- Для изменённого опкода — ручной прогон через `vm.run(pc)`.
