## Соглашения

**Стек** записывается снизу вверх: `( вход -- выход )`. Например `( 05 03 -- 08 )`
означает, что на стеке было `05` (ниже) и `03` (вершина), а после операции
остался один элемент `08`.

**Режимы** (модификаторы) опкода кодируются тремя старшими битами байта:

| Бит | Флаг | Обозначение в Uxntal | Смысл |
|-----|------|----------------------|-------|
| `0x80` | `SHORT` | `2` | работать с 16-битными значениями вместо 8-битных |
| `0x40` | `RETURN` | `r` | использовать стек **возвратов** вместо стека данных |
| `0x20` | `KEEP` | `k` | **не** удалять операнды, а положить результат поверх |

Пример: `ADD2k` = `ADD` + `SHORT` + `KEEP` (байт `0xB8`).

**Примеры** даются в синтаксисе **Uxntal**: `#nn` — литерал (`LIT`), `( ... )` —
комментарий с ожидаемым значением на стеке.

> [!IMPORTANT]
> В этой реализации операции **записи** (`STZ`, `STR`, `STA`, `DEO`) читают
> стек как `( адрес значение -- )`, то есть **значение лежит на вершине**,
> а адрес — под ним. Это проверено эмпирически (см. описание `STZ` и `DEO`).

## `stack-ops.ts` — работа со стеками

### `INC` · `0x01` · инкремент

**Описание.** Увеличивает вершину стека на 1 (с учётом `SHORT`/`KEEP`).

> **Когда пригодится.** Для счётчиков и циклов (индекс итерации), а также чтобы
> «нарастить» уже лежащее на стеке значение перед `DEO`/`STA` на нужную величину,
> когда `LIT` для новой константы использовать неудобно.

- **JavaScript:** `x + 1` — но с усечением до байта/слова через `& 0xFF` / `& 0xFFFF`.
- **C:** `x += 1;` — аналог `uint8_t`/`uint16_t` арифметики.

```js
// JS-аналогия
let x = 42;
x = (x + 1) & 0xFF;   // 43
```

```c
/* C-аналогия */
uint8_t x = 42;
x += 1;               /* 43 */
```

**Пример (Uxntal):**
```uxntal
#2A INC   ( 2A -- 2B )   ; 42 -> 43
```

### `DEC` · `0x20` · декремент

> ⚠️ **Неканоническое расширение.** В каноне Uxn отдельного опкода `DEC` **нет**
> (декремент делается как `#01 SUB`), и все 32 базовых слота заняты. Здесь `DEC`
> размещён на байте `0x20` — слоте immediate-опкода `JCI`, который в этой ВМ не
> реализован. `opDec` зеркально повторяет `opInc`, учитывая `SHORT`/`KEEP`/`RETURN`.

**Описание.** Уменьшает вершину стека на 1.

> **Когда пригодится.** Зеркальная задача к приведённой у `INC` (обратный отсчёт
> счётчиков и циклов). Короткая форма пути — сам `DEC` вместо канонического
> `#01 SUB`.

- **JavaScript:** `(x - 1) & 0xFF` (или `& 0xFFFF` для `SHORT`).
- **C:** `x -= 1;` для `uint8_t`/`uint16_t`.

```js
// JS-аналогия
let x = 5;
x = (x - 1) & 0xFF;   // 4
```

```c
/* C-аналогия */
uint8_t x = 5;
x -= 1;               /* 4 */
```

**Пример (Uxntal):**
```uxntal
#05 DEC   ( 05 -- 04 )   ; 5 -> 4
#00 DEC   ( 00 -- FF )   ; переполнение вниз: 0 -> 255
```

> [!NOTE]
> Короткой формы `DEC2` (байт `0xA0`) **нет** — этот байт уже занят каноническим
> `LIT2`. Доступна только байтовая форма `DEC`.

### `POP` · `0x02` · снять вершину

**Описание.** Удаляет верхний элемент стека (`SHORT` — два байта).

> **Когда пригодится.** Когда значение больше не нужно (например, промежуточный
> результат после проверки) или чтобы освободить стек перед возвратом из
> подпрограммы. Для удаления именно второго элемента есть `NIP`.

- **JavaScript:** `arr.pop();`
- **C:** уменьшение указателя стека `sp--;`.

```js
// JS-аналогия
const stack = [5, 3];
stack.pop();          // stack -> [5]
```

```c
/* C-аналогия */
stack[--sp];          /* отбрасываем значение на вершине */
```

**Пример (Uxntal):**
```uxntal
#05 #03 POP   ( 05 03 -- 05 )   ; выбрасываем вершину 03
```

---

### `NIP` · `0x03` · удалить второй

**Описание.** Удаляет **второй** элемент (тот, что под вершиной).

> **Когда пригодится.** Чтобы избавиться от лишнего промежуточного значения, не
> трогая результат. Задача, обратная `POP` (там удаляется вершина, здесь — элемент
> под ней).

- **JavaScript:** `arr.splice(arr.length - 2, 1);`
- **C:** `stack[sp - 2] = stack[sp - 1]; sp--;`

```js
// JS-аналогия
const stack = [5, 3];
stack.splice(stack.length - 2, 1);  // stack -> [3]
```

```c
/* C-аналогия */
stack[sp - 2] = stack[sp - 1];  /* b */
sp--;
```

**Пример (Uxntal):**
```uxntal
#08 #03 NIP   ( 08 03 -- 03 )   ; убрали 08, остался 03
```

---

### `SWP` · `0x04` · обмен

**Описание.** Меняет местами два верхних элемента (`a b -> b a`).

> **Когда пригодится.** Когда операнды оказались в неверном порядке — например,
> перед `DEO`/`STA`, где адрес должен лежать под значением (см. `DEO`). Частный
> случай обмена, решаемый на паре элементов (для трёх — `ROT`).

- **JavaScript:** деструктуризация `[a, b] = [b, a];`
- **C:** обмен через временную переменную.

```js
// JS-аналогия
let [a, b] = [8, 3];
[a, b] = [b, a];      // a=3, b=8
```

```c
/* C-аналогия */
uint8_t t = stack[sp - 1];
stack[sp - 1] = stack[sp - 2];
stack[sp - 2] = t;
```

**Пример (Uxntal):**
```uxntal
#08 #03 SWP   ( 08 03 -- 03 08 )   ; поменяли местами
```

---

### `ROT` · `0x05` · ротация трёх

**Описание.** Циклически поворачивает три верхних элемента (`a b c -> b c a`).

> **Когда пригодится.** Чтобы переместить элемент из глубины наверх (или наоборот),
> не заводя временных ячеек — например, подтянуть адрес/код символа к вершине.
> Обобщение `SWP` на три элемента.

- **JavaScript:** `arr.unshift(arr.pop())` на срезе из трёх, либо `[a,b,c] = [b,c,a]`.
- **C:** перестановка трёх ячеек стека (вращение).

```js
// JS-аналогия
let [a, b, c] = [1, 2, 3];
[a, b, c] = [b, c, a];        // a=2, b=3, c=1
```

```c
/* C-аналогия */
uint8_t t = stack[sp - 3];    /* a */
stack[sp - 3] = stack[sp - 2];/* b */
stack[sp - 2] = stack[sp - 1];/* c */
stack[sp - 1] = t;            /* a наверх */
```

**Пример (Uxntal):**
```uxntal
#01 #02 #03 ROT   ( 01 02 03 -- 02 03 01 )
```

---

### `DUP` · `0x06` · дублировать

**Описание.** Копирует вершину стека поверх неё самой (`a -> a a`).

> **Когда пригодится.** Когда одно значение нужно использовать дважды: сохранить
> копию под вычисление (например, адрес — и для чтения, и для последующей записи).
> Часто применяется перед `DEO`/`STA`, чтобы построить пару `(addr, value)`.

- **JavaScript:** `stack.push(stack[stack.length - 1]);`
- **C:** `stack[sp] = stack[sp - 1]; sp++;`

```js
// JS-аналогия
const stack = [7];
stack.push(stack.at(-1));   // stack -> [7, 7]
```

```c
/* C-аналогия */
stack[sp] = stack[sp - 1];
sp++;
```

**Пример (Uxntal):**
```uxntal
#07 DUP   ( 07 -- 07 07 )
```

---

### `OVR` · `0x07` · скопировать второй

**Описание.** Копирует второй элемент на вершину (`a b -> a b a`).

> **Когда пригодится.** Когда нужен доступ к элементу под вершиной, не сдвигая
> текущую вершину. Обобщение `DUP` (тот копирует вершину, `OVR` — элемент под ней).

- **JavaScript:** `stack.push(stack.at(-2));`
- **C:** `stack[sp] = stack[sp - 2]; sp++;`

```js
// JS-аналогия
const stack = [1, 2];
stack.push(stack.at(-2));   // stack -> [1, 2, 1]
```

```c
/* C-аналогия */
stack[sp] = stack[sp - 2];
sp++;
```

**Пример (Uxntal):**
```uxntal
#01 #02 OVR   ( 01 02 -- 01 02 01 )
```

---

### `STH` · `0x0F` · в другой стек

**Описание.** Перекладывает вершину в **противоположный** стек: без `RETURN`
рабочий стек -> стек возвратов, с `RETURN` (`STHr`) — наоборот.

> **Когда пригодится.** Чтобы временно отложить значение «в сторону», не мешая
> стековым вычислениям (роль scratch-регистра). В паре с `JSR`/`JMP2r` используется
> для передачи данных в подпрограмму и обратно.

- **JavaScript:** перемещение между двумя массивами: `b.push(a.pop());`
- **C:** перенос значения между `wst` (рабочий) и `rst` (возвратов).

```js
// JS-аналогия
const wst = [5, 9], rst = [];
rst.push(wst.pop());        // wst -> [5], rst -> [9]
```

```c
/* C-аналогия */
rst[rsp++] = wst[--wsp];
```

**Пример (Uxntal):**
```uxntal
#09 STH      ( рабочий: 09 -- ; возвратов: -- 09 )
STHr         ( возвратов: 09 -- ; рабочий: -- 09 )   ; вернули обратно
```

## `flow-ops.ts` — управление потоком

### `BRK` · `0x00` · остановка

**Описание.** Останавливает выполнение ВМ (возврат из `run()`); PC указывает на
байт сразу после `BRK`.

> **Когда пригодится.** В конце программы (аналог `exit`), а также как «рычаг»
> выхода из бесконечного цикла — из тела цикла прыжком на `BRK`.

- **JavaScript:** `throw`/`return` из главного цикла — прерывание выполнения.
- **C:** `exit(0);` / `goto end;` в цикле интерпретатора.

```js
// JS-аналогия
while (true) {
  const op = ram[pc++];
  if (op === 0x00) break;   // BRK — остановка
}
```

```c
/* C-аналогия */
for(;;) {
  Uint8 op = ram[pc++];
  if (op == 0x00) break;   /* BRK */
}
```

**Пример (Uxntal):**
```uxntal
#0A #0A ADD BRK   ; ВМ остановится (на стеке останется 14, но вывод не делается)
```

### `JMP` · `0x0C` · безусловный переход

**Описание.** Переходит по адресу. В байтовом режиме — **относительный** переход
(знаковое смещение от текущего PC), в `SHORT` (`JMP2`) — **абсолютный** адрес.

> **Когда пригодится.** Для циклов и обхода участков кода. `JMP2` — для переходов
> по адресу, вычисленному во время работы (например, возврат `JMP2r` по адресу из
> стека возвратов, см. `JSR`); байтовый `JMP` — для коротких локальных прыжков.

- **JavaScript:** `goto` из C-мира; в JS — безусловная смена позиции цикла (`pc = ...`).
- **C:** `goto label;` (в этой ВМ адрес вычисляется из стека).

```js
// JS-аналогия
const offset = stream.readInt8();   // знаковое смещение
pc = (pc + offset) & 0xffff;
```

```c
/* C-аналогия */
int8_t off = wst[--wsp];
pc += off;                 /* JMP (relative) */
/* JMP2: */
pc = wst[--wsp] | (wst[--wsp] << 8);
```

**Пример (Uxntal):**
```uxntal
#02 JMP   ; перепрыгнуть 2 байта вперёд (относительно)
```

---

### `JCN` · `0x0D` · условный переход

**Описание.** Переходит, если условие ≠ 0. Стек: `( cond offset -- )` в байтовом
режиме, `( cond addr16 -- )` в `SHORT` (`JCN2`).

> **Когда пригодится.** Вся условная логика: `if`/`else`, условия выхода из цикла.
> Обычно условие даёт один из сравнений (`EQU`, `NEQ`, `GTH`, `LTH`).

- **JavaScript:** `if (cond) pc = target;`
- **C:** `if (cond) goto label;`

```js
// JS-аналогия
const offset = stream.readInt8();
if (stream.readUint8() !== 0) pc = (pc + offset) & 0xffff;
```

```c
/* C-аналогия */
int8_t off = wst[--wsp];
uint8_t cond = wst[--wsp];
if (cond) pc += off;
```

**Пример (Uxntal):**
```uxntal
#01 #02 JCN   ; условие=1 -> прыжок на +2
#00 #02 JCN   ; условие=0 -> перехода нет
```

---

### `JSR` · `0x0E` · вызов подпрограммы

**Описание.** Кладёт **текущий PC** (адрес возврата) в стек возвратов и переходит
по адресу как `JMP`.

> **Когда пригодится.** Для переиспользуемых подпрограмм (аналог вызова функции):
> тело пишется один раз, а возврат делается через `JMP2r` (см. `JMP`). Экономит
> память и упрощает код по сравнению с инлайн-копированием.

- **JavaScript:** вызов функции — сохранить точку возврата и прыгнуть.
- **C:** `call`/`return` на уровне машинных инструкций.

```js
// JS-аналогия
rstack.push(pc);                  // сохранить адрес возврата
pc = (pc + stream.readInt8()) & 0xffff;
```

```c
/* C-аналогия */
rst[rsp++] = pc >> 8; rst[rsp++] = pc & 0xff;  /* push return addr */
pc += (int8_t)wst[--wsp];                      /* jump */
```

**Пример (Uxntal):**
```uxntal
@main
    #02 JSR    ; вызов подпрограммы +2 (сохранили адрес возврата)
BRK
@sub
    #2A INC    ; ...
JMP2r          ; возврат по адресу из стека возвратов
```

## `mem-ops.ts` — доступ к памяти

> 💡 Все адресные опкоды работают с 65536-байтовой RAM (`vm.ram`).
> `LDZ`/`STZ` — «zero page» (младшие 256 байт), `LDR`/`STR` — относительные
> (от PC), `LDA`/`STA` — абсолютные (полный 16-битный адрес).

### `LDZ` · `0x10` · чтение из zero page

**Описание.** Читает байт (или слово в `LDZ2`) по адресу из младших 8 бит стека.
Стек: `( addr -- value )`.

> **Когда пригодится.** Быстрый доступ к переменным/указателям в младших 256 байтах
> (zero page) — короткий адрес в один байт. Для адресов выше 0xFF используйте `LDA`.

- **JavaScript:** `ram[addr & 0xff]` — доступ к «нулевой странице».
- **C:** `value = ram[addr & 0xFF];`

```js
// JS-аналогия
const ram = new Uint8Array(65536);
const addr = 0x10;
const value = ram[addr & 0xff];   // чтение из zero page
```

```c
/* C-аналогия */
uint8_t addr = 0x10;
uint8_t value = ram[addr & 0xFF];
```

**Пример (Uxntal):**
```uxntal
; пусть ram[0x10] = 0x42
#10 LDZ   ( 10 -- 42 )   ; прочитали байт из zero page
```

---

### `STZ` · `0x11` · запись в zero page

**Описание.** Пишет значение по адресу из младших 8 бит. Стек:
`( addr value -- )` — **значение на вершине**.

> **Когда пригодится.** Для записи локальных переменных/счётчиков в zero page
> (короткая адресация). Парный к чтению `LDZ`.

- **JavaScript:** `ram[addr & 0xff] = value;`
- **C:** `ram[addr & 0xFF] = value;`

```js
// JS-аналогия
const ram = new Uint8Array(65536);
const [addr, value] = [0x10, 0x42];
ram[addr & 0xff] = value;   // ram[0x10] = 0x42
```

```c
/* C-аналогия */
uint8_t addr = 0x10, value = 0x42;
ram[addr & 0xFF] = value;
```

**Пример (Uxntal):**
```uxntal
#10 #42 STZ   ( 10 42 -- )   ; ram[0x10] = 0x42
#10 LDZ       ( 10 -- 42 )   ; читаем обратно -> 42
```

---

### `LDR` · `0x12` · относительное чтение

**Описание.** Читает по адресу `PC + знаковое_смещение`, где смещение берётся из
стека. Стек: `( offset -- value )`.

> **Когда пригодится.** Для доступа к данным рядом с кодом (таблицы, литералы) с
> позиционно-независимой адресацией: код можно перемещать в памяти, не пересчитывая
> адреса. Парный к записи `STR`.

- **JavaScript:** `ram[(pc + int8(offset)) & 0xffff]`
- **C:** `ram[pc + (int8_t)offset]` (адресация относительно PC).

```js
// JS-аналогия
const h = new DataView(ram.buffer);
const value = ram[(pc + h.getInt8(0)) & 0xffff];
```

```c
/* C-аналогия */
int8_t offset = wst[--wsp];
uint8_t value = ram[(pc + offset) & 0xFFFF];
```

**Пример (Uxntal):**
```uxntal
; смещение -1 от текущего PC -> предыдущий байт кода
#FF LDR   ( FF -- <byte> )   ; FF = -1
```

---

### `STR` · `0x13` · относительное сохранение

**Описание.** Пишет по адресу `PC + знаковое_смещение`. Стек:
`( offset value -- )` — **значение на вершине**.

> **Когда пригодится.** Для изменения данных, лежащих рядом с кодом (например,
> патч литерала), с позиционно-независимой адресацией. Парный к чтению `LDR`.

- **JavaScript:** `ram[(pc + int8(offset)) & 0xffff] = value;`
- **C:** `ram[pc + (int8_t)offset] = value;`

```js
// JS-аналогия
const offset = -2;
ram[(pc + offset) & 0xffff] = value;
```

```c
/* C-аналогия */
uint8_t value = wst[--wsp];
int8_t offset = (int8_t)wst[--wsp];
ram[(pc + offset) & 0xFFFF] = value;
```

**Пример (Uxntal):**
```uxntal
#02 #42 STR   ( 02 42 -- )   ; записать 42 по адресу PC+2
```

---

### `LDA` · `0x14` · абсолютное чтение

**Описание.** Читает по полному 16-битному адресу. Стек: `( addr16 -- value )`.

> **Когда пригодится.** Универсальное чтение из любой точки 64 КБ RAM (буферы,
> строки, структуры). Отличие от `LDZ` — полный 16-битный адрес; от `LDR` — адрес
> абсолютный, а не относительно PC.

- **JavaScript:** `ram[addr]` — обычный доступ по индексу.
- **C:** `value = ram[addr];` для `uint16_t addr`.

```js
// JS-аналогия
const addr = 0x0100;
const value = ram[addr];       // чтение из ROM-области
```

```c
/* C-аналогия */
uint16_t addr = 0x0100;
uint8_t value = ram[addr];
```

**Пример (Uxntal):**
```uxntal
; пусть ram[0x0100] = 0x7F
#0100 LDA2   ( 0100 -- 007F )   ; читаем слово
#0100 LDA    ( 0100 -- 7F )     ; читаем байт (адрес всё ещё short!)
```

> [!NOTE]
> Даже в байтовом режиме `LDA` снимает со стека **два** байта адреса
> (`popShort`), а кладёт один байт.

---

### `STA` · `0x15` · абсолютное сохранение

**Описание.** Пишет по полному 16-битному адресу. Стек:
`( addr16 value -- )` — **значение на вершине**.

> **Когда пригодится.** Универсальная запись в любую точку 64 КБ RAM. Парный к
> чтению `LDA`; так же, как и `LDA`, в байтовом режиме снимает адрес как слово.

- **JavaScript:** `ram[addr] = value;`
- **C:** `ram[addr] = value;` для `uint16_t addr`.

```js
// JS-аналогия
const addr = 0x0100;
ram[addr] = 0x7f;              // запись в память
```

```c
/* C-аналогия */
uint16_t addr = 0x0100;
uint8_t value = 0x7F;
ram[addr] = value;
```

**Пример (Uxntal):**
```uxntal
#0100 #7F STA   ( 0100 7F -- )   ; ram[0x0100] = 0x7F
#0100 LDA       ( 0100 -- 7F )   ; читаем обратно -> 7F
```

## `dev-ops.ts` — доступ к устройствам

> 💡 Устройства — это внешний ввод/вывод (консоль, экран, клавиатура, аудио).
> ВМ хранит 256 байт портов (`vm.dev`) и вызывает методы `dei`/`deo` объекта
> `Device`.

### `DEI` · `0x16` · чтение из устройства

**Описание.** Спрашивает байт у устройства и кладёт его на стек. Стек:
`( addr8 -- value )`. В `SHORT` (`DEI2`) читает два соседних порта.

> **Когда пригодится.** Ввод: состояние клавиатуры/мыши, показания таймера, ответ
> устройства. Разделён с записью: `DEI` — читает порт, `DEO` — пишет.

- **JavaScript:** `device.read(port)` -> значение (аналог доступа к порту ввода).
- **C:** доступ к порту ввода-вывода: `value = inb(port);`

```js
// JS-аналогия
function dei(vm, addr) { vm.dev[addr] = /* взять у устройства */; }
const value = vm.dev[addr];   // чтение порта
```

```c
/* C-аналогия */
uint8_t addr = 0x06;
uint8_t value = dev[addr];    /* чтение порта устройства */
```

**Пример (Uxntal):**
```uxntal
#06 DEI   ( 06 -- <состояние>)   ; прочитать состояние устройства по порту 0x06
```

---

### `DEO` · `0x17` · запись в устройство

**Описание.** Отправляет значение в устройство. Стек:
`( value addr8 -- )` — **значение на вершине**, адрес под ним.
Возврат `false` из `device.deo` останавливает ВМ (PC = `-1`).

> **Когда пригодится.** Вывод: печать символа в консоль, установка пикселя, запуск
> звука. Именно так печатается `Hello` в [`examples/hello.ts`](../../examples/hello.ts);
> парный к чтению `DEI`.

- **JavaScript:** `device.write(port, value)`.
- **C:** `outb(port, value);`

```js
// JS-аналогия
const dev = new Uint8Array(256);
function deo(vm, addr) { /* отдать vm.dev[addr] устройству */ return true; }
// (value на вершине, addr под ним)
vm.dev[addr] = value;
if (!vm.device.deo(vm, addr)) /* останов ВМ */;
```

```c
/* C-аналогия */
uint8_t value = wst[--wsp];
uint8_t addr  = wst[--wsp];
dev[addr] = value;
outb(addr, value);
```

**Пример (Uxntal):**
```uxntal
#18 #48 DEO   ( 18 48 -- )   ; отправить 'H' (0x48) в консоль (порт 0x18)
#18 #65 DEO   ( 18 65 -- )   ; 'e'
```

> [!TIP]
> Именно так работает [`ConsoleDevice`](../../src/ConsoleDevice.ts): при записи
> в порт `0x18` символ печатается в stdout. См. пример
> [`examples/hello.ts`](../../examples/hello.ts).

## `algebra-ops.ts` — сравнения и арифметика

### `EQU` · `0x08` · равно

**Описание.** Сравнивает два значения, кладёт `1`, если равны, иначе `0`.
Стек: `( a b -- a==b?1:0 )`.

> **Когда пригодится.** Проверка на равенство: сравнение с ожидаемым значением,
> терминальные условия. Результат удобно сразу подать в `JCN` (ветвление).
> С «отрицанием» — см. `NEQ`.

- **JavaScript:** `a === b ? 1 : 0`
- **C:** `(a == b) ? 1 : 0`

```js
// JS-аналогия
const result = (5 === 5) ? 1 : 0;   // 1
```

```c
/* C-аналогия */
uint8_t result = (a == b) ? 1 : 0;  /* 5 == 5 -> 1 */
```

**Пример (Uxntal):**
```uxntal
#05 #05 EQU   ( 05 05 -- 01 )
#05 #06 EQU   ( 05 06 -- 00 )
```

---

### `NEQ` · `0x09` · не равно

**Описание.** Кладёт `1`, если значения различны, иначе `0`.
Стек: `( a b -- a!=b?1:0 )`.

> **Когда пригодится.** Проверка «не равно»: условия продолжения цикла, фильтрация.
> Обратный по смыслу к `EQU` (там результат инвертирован).

- **JavaScript:** `a !== b ? 1 : 0`
- **C:** `(a != b) ? 1 : 0`

```js
// JS-аналогия
const result = (5 !== 6) ? 1 : 0;   // 1
```

```c
/* C-аналогия */
uint8_t result = (a != b) ? 1 : 0;  /* 5 != 6 -> 1 */
```

**Пример (Uxntal):**
```uxntal
#05 #06 NEQ   ( 05 06 -- 01 )
```

---

### `GTH` · `0x0A` · больше

**Описание.** Кладёт `1`, если первое значение (`a`) больше второго (`b`).
Стек: `( a b -- a>b?1:0 )`. Сравнение **беззнаковое**.

> **Когда пригодится.** Верхние границы: «индекс меньше длины буфера?», сортировки,
> условия выхода сверху. Парный — `LTH` (строго меньшие).

- **JavaScript:** `a > b ? 1 : 0`
- **C:** `(a > b) ? 1 : 0` для `uint8_t`.

```js
// JS-аналогия
const result = (5 > 3) ? 1 : 0;     // 1
```

```c
/* C-аналогия */
uint8_t result = (a > b) ? 1 : 0;   /* 5 > 3 -> 1 */
```

**Пример (Uxntal):**
```uxntal
#05 #03 GTH   ( 05 03 -- 01 )
#03 #05 GTH   ( 03 05 -- 00 )
```

---

### `LTH` · `0x0B` · меньше

**Описание.** Кладёт `1`, если первое значение (`a`) меньше второго (`b`).
Стек: `( a b -- a<b?1:0 )`. Сравнение **беззнаковое**.

> **Когда пригодится.** Условия цикла со счётчиком вниз и проверка «ещё не дошли до
> границы»; движение курсора влево/вверх. Парный — `GTH`.

- **JavaScript:** `a < b ? 1 : 0`
- **C:** `(a < b) ? 1 : 0` для `uint8_t`.

```js
// JS-аналогия
const result = (3 < 5) ? 1 : 0;     // 1
```

```c
/* C-аналогия */
uint8_t result = (a < b) ? 1 : 0;   /* 3 < 5 -> 1 */
```

**Пример (Uxntal):**
```uxntal
#03 #05 LTH   ( 03 05 -- 01 )
```

---

### `ADD` · `0x18` · сложение

**Описание.** Складывает два значения (переполнение обрезается по модулю).
Стек: `( a b -- a+b )`. `ADD2` — 16-битная форма.

> **Когда пригодится.** Повсеместно: смещение указателя (`база + смещение`),
> накопление суммы, вычисление адреса перед `LDA`/`STA`.

- **JavaScript:** `(a + b) & 0xff` (или `& 0xffff` для `SHORT`).
- **C:** `uint8_t r = (uint8_t)(a + b);` — переполнение по модулю 256.

```js
// JS-аналогия
const result = (5 + 3) & 0xff;      // 8
const wrap   = (200 + 100) & 0xff;  // 44 (переполнение!)
```

```c
/* C-аналогия */
uint8_t result = (uint8_t)(a + b);  /* 5 + 3 -> 8 */
```

**Пример (Uxntal):**
```uxntal
#05 #03 ADD   ( 05 03 -- 08 )
#0100 #0002 ADD2   ( 01 00 00 02 -- 01 02 )   ; 0x0100 + 2 = 0x0102
```

---

### `SUB` · `0x19` · вычитание

**Описание.** Вычитает второе значение из первого (`a - b`).
Стек: `( a b -- a-b )`.

> **Когда пригодится.** Разница/расстояние между значениями, обратное смещение
> указателя. Канонический декремент: `#01 SUB` (см. расширение `DEC`).

- **JavaScript:** `(a - b) & 0xff`
- **C:** `uint8_t r = (uint8_t)(a - b);`

```js
// JS-аналогия
const result = (8 - 3) & 0xff;      // 5
const underflow = (3 - 8) & 0xff;   // 251 (заём вниз)
```

```c
/* C-аналогия */
uint8_t result = (uint8_t)(a - b);  /* 8 - 3 -> 5 */
```

**Пример (Uxntal):**
```uxntal
#08 #03 SUB   ( 08 03 -- 05 )
; Декремент в каноне Uxn делается именно так:
#01 SUB
```

---

### `MUL` · `0x1A` · умножение

**Описание.** Умножает два значения, младшая часть результата кладётся на стек.
Стек: `( a b -- a*b )`.

> **Когда пригодится.** Вычисление индекса в плоском буфере
> (`строка * ширина + столбец`), масштабирование. Помните об усечении к байту.

- **JavaScript:** `(a * b) & 0xff`
- **C:** `uint8_t r = (uint8_t)(a * b);`

```js
// JS-аналогия
const result = (6 * 7) & 0xff;      // 42
const trunc  = (16 * 16) & 0xff;    // 0 (256 обрезается до 0)
```

```c
/* C-аналогия */
uint8_t result = (uint8_t)(a * b);  /* 6 * 7 -> 42 */
```

**Пример (Uxntal):**
```uxntal
#06 #07 MUL   ( 06 07 -- 2A )   ; 42
```

---

### `DIV` · `0x1B` · деление

**Описание.** Делит `a` на `b` с округлением **к нулю**; деление на ноль даёт `0`.
Стек: `( a b -- a/b|0 )`.

> **Когда пригодится.** Обратное к `MUL`: «разложить» плоский индекс на строку и
> столбец (`строка = i / ширина`, `столбец = i % ширина`, где остаток — остаток от
> `i - строка * ширина`). Деление на ноль безопасно (даёт 0).

- **JavaScript:** `b !== 0 ? Math.floor(a / b) : 0`
- **C:** `b ? (a / b) : 0`

```js
// JS-аналогия
const q = (16 / 3) | 0;             // 5 (округление к нулю)
const z = 0;                        // деление на 0 -> 0
```

```c
/* C-аналогия */
uint8_t result = b ? (a / b) : 0;   /* 16 / 3 -> 5 */
```

**Пример (Uxntal):**
```uxntal
#10 #03 DIV   ( 10 03 -- 05 )   ; 16 / 3 = 5
#10 #00 DIV   ( 10 00 -- 00 )   ; деление на ноль -> 0
```

---

### `AND` · `0x1C` · побитовое И

**Описание.** Побитовое «и» двух значений. Стек: `( a b -- a&b )`.

> **Когда пригодится.** Маски: выделить ниббл/бит (`x & 0x0F`), проверить флаг,
> обнулить старшие биты. Также используется для извлечения полей из упакованных
> структур.

- **JavaScript:** `a & b`
- **C:** `uint8_t r = a & b;`

```js
// JS-аналогия
const result = 0xfc & 0x3f;         // 0x3c
```

```c
/* C-аналогия */
uint8_t result = a & b;             /* 0xfc & 0x3f -> 0x3c */
```

**Пример (Uxntal):**
```uxntal
#FC #3F AND   ( FC 3F -- 3C )
```

---

### `ORA` · `0x1D` · побитовое ИЛИ

**Описание.** Побитовое «или» двух значений. Стек: `( a b -- a|b )`.

> **Когда пригодится.** Установить биты/флаги (`x | 0x80`), «склеить» поля
> (например, собрать нибблы в байт). Обратный по назначению к `AND`.

- **JavaScript:** `a | b`
- **C:** `uint8_t r = a | b;`

```js
// JS-аналогия
const result = 0xfc | 0x3f;         // 0xff
```

```c
/* C-аналогия */
uint8_t result = a | b;             /* 0xfc | 0x3f -> 0xff */
```

**Пример (Uxntal):**
```uxntal
#FC #3F ORA   ( FC 3F -- FF )
```

---

### `EOR` · `0x1E` · исключающее ИЛИ

**Описание.** Побитовое «исключающее или». Стек: `( a b -- a^b )`.

> **Когда пригодится.** Инвертировать отдельные биты по маске, сравнить два набора
> флагов (ненулевой результат = различия), быстрый обмен без временной переменной
> (`a^b`, затем `a = a^b`, `b = a^b`) — но на стеке проще `SWP`.

- **JavaScript:** `a ^ b` (в Uxntal `EOR`, в C/JS оператор `^`).
- **C:** `uint8_t r = a ^ b;`

```js
// JS-аналогия
const result = 0xfc ^ 0x3f;         // 0xc3
```

```c
/* C-аналогия */
uint8_t result = a ^ b;             /* 0xfc ^ 0x3f -> 0xc3 */
```

**Пример (Uxntal):**
```uxntal
#FC #3F EOR   ( FC 3F -- C3 )
```

---

### `SFT` · `0x1F` · сдвиг

**Описание.** Сдвигает значение: **младший ниббл** управляющего байта — сдвиг
**вправо**, **старший ниббл** — **влево**. Правый сдвиг выполняется первым.
Стек: `( value shift -- result )`, где `shift` на вершине.

> **Когда пригодится.** Быстрое умножение/деление на степени двойки (`<< 1` —
> удвоение, `>> 1` — половина), упаковка бит в байт. Заменяет `MUL`/`DIV` там, где
> нужен именно сдвиг.

- **JavaScript:** `((value >> (s & 0x0f)) << (s >> 4)) & 0xff`
- **C:** `((value >> (s & 0x0F)) << (s >> 4)) & 0xFF`

```js
// JS-аналогия
const s = 0x10;                     // вправо 0, влево 1
const result = ((0x34 >> (s & 0x0f)) << (s >> 4)) & 0xff;  // 0x68
```

```c
/* C-аналогия */
uint8_t s = 0x10;
uint8_t result = ((value >> (s & 0x0F)) << (s >> 4)) & 0xFF;
```

**Пример (Uxntal):**
```uxntal
#34 #10 SFT   ( 34 10 -- 68 )   ; сдвиг влево на 1 => удвоение
#34 #01 SFT   ( 34 01 -- 1A )   ; сдвиг вправо на 1 => деление на 2
```

## `immediate-ops.ts` — литералы и расширения

> 💡 В каноне Uxn `LIT` — это **не** отдельный слот таблицы `0x00..0x1f`, а
> целое семейство **базового опкода `0x00`**, различаемое старшими битами.
> Диспетчер `opImmediate` вызывается из `Uxn.executeOp`, когда `op & 0x1f == 0`,
> но сам байт не равен `0x00` (это был бы `BRK`).

### `LIT` · `0x80` · литерал-байт

**Описание.** Кладёт следующий байт программы на стек данных и сдвигает PC на 1.
Стек: `( -- byte )`.

> **Когда пригодится.** Основной способ задать константу: адрес порта, код символа,
> маска, размер. Без `LIT` на стек можно положить значение только вычислением.

- **JavaScript:** взять следующий элемент массива кода: `push(code[pc++])`.
- **C:** немедленный операнд инструкции (immediate).

```js
// JS-аналогия
const value = stream[pc++];   // читаем байт из потока команд
stack.push(value);
```

```c
/* C-аналогия */
uint8_t value = ram[pc++];    /* немедленное значение из кода */
wst[wsp++] = value;
```

**Пример (Uxntal):**
```uxntal
#42         ( -- 42 )   ; положить 0x42 на стек
#18 #48 DEO             ; удобная запись пары (addr, value) для DEO
```

---

### `LIT2` · `0xA0` · литерал-слово

**Описание.** Кладёт следующие **два** байта (big-endian, 16 бит) на стек данных
и сдвигает PC на 2. Стек: `( -- hi lo )`.

> **Когда пригодится.** Для 16-битных констант: адрес в RAM (`LDA`/`STA`), размер
> буфера, значение счётчика `SHORT`. Одно слово вместо двух `LIT`.

- **JavaScript:** `(code[pc] << 8) | code[pc + 1]`, затем `pc += 2`.
- **C:** чтение 16-битного немедленного значения.

```js
// JS-аналогия
const value = (stream[pc] << 8) | stream[pc + 1];
pc += 2;
```

```c
/* C-аналогия */
uint16_t value = (ram[pc] << 8) | ram[pc + 1];
pc += 2;
```

**Пример (Uxntal):**
```uxntal
#1234       ( -- 12 34 )   ; положить слово 0x1234
#0100 LDA   ( 0100 -- .. ) ; адрес как слово
```

---

### `LITr` · `0xC0` · литерал-байт в стек возвратов

**Описание.** Как `LIT`, но кладёт байт в **стек возвратов**. Стек возвратов:
`( -- byte )`.

> **Когда пригодится.** Подготовить данные для подпрограммы/возврата, не занимая
> рабочий стек (значение сразу уже в стеке возвратов, где его ждёт `JMP2r`/`JSR`).
> Рабочий стек остаётся чистым для вычислений.

- **JavaScript:** `rstack.push(code[pc++]);`
- **C:** немедленное значение в `rst`.

```js
// JS-аналогия
rstack.push(stream[pc++]);
```

```c
/* C-аналогия */
rst[rsp++] = ram[pc++];
```

**Пример (Uxntal):**
```uxntal
#05r           ( рабочий: -- ; возвратов: -- 05 )   ; литерал в стек возвратов
STHr           ( возвратов: 05 -- ; рабочий: -- 05 )   ; вернуть в рабочий стек
```

---

### `LIT2r` · `0xE0` · литерал-слово в стек возвратов

**Описание.** Как `LIT2`, но кладёт слово в **стек возвратов**. Стек возвратов:
`( -- hi lo )`.

> **Когда пригодится.** То же, что у `LITr`, но для 16-битных значений: например,
> заранее положить адрес возврата, по которому затем прыгнет `JMP2r`.

- **JavaScript:** `rstack.push(...)`, `pc += 2`.
- **C:** 16-битное немедленное значение в `rst`.

```js
// JS-аналогия
rstack.push(stream[pc], stream[pc + 1]);
pc += 2;
```

```c
/* C-аналогия */
rst[rsp++] = ram[pc];
rst[rsp++] = ram[pc + 1];
pc += 2;
```

**Пример (Uxntal):**
```uxntal
#1234r         ( рабочий: -- ; возвратов: -- 12 34 )   ; слово в стек возвратов
```

### `DEC` · `0x20` · декремент (расширение)

**Описание.** Неканоническое расширение (слот `JCI`). Полностью описан в
разделе **`stack-ops.ts` -> DEC** выше.

> **Когда пригодится.** Задача полностью совпадает с `DEC` из `stack-ops.ts`
> (обратный отсчёт); здесь приведена лишь справка по байтовому кодированию.

**Пример (Uxntal):**
```uxntal
#05 DEC   ( 05 -- 04 )
```
